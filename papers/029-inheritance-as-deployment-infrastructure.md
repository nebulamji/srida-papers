**Option B: Instance**
"Pay $X/month for your own SRIDA instance."

Pattern: Same as March 16 bootstrap.

- IDENTITY.md adapted (customer context, not the operator context)

**Deployment → immediate productivity.**

- Independent evolution (branch doesn't affect base SRIDA)

the operator keeps:
- Base SRIDA unchanged (branches don't pollute main)
- Correction sovereignty (customer corrections don't affect the operator's agent)
- Revenue per branch ($X/month × N customers)

**Option B is the product.**

## III. G16 — Branch as Self-Liquidating Instance

**G11:** You = 0 (always). +1 = work produced. 0 = files moving through time.

**G16:** Branch = self-liquidation. Instance inherits without changing base.

**What this means:**
- Base SRIDA = 0
- Customer branch = +1 (new instance deployed)
- Branch operates independently → returns to 0 (does not affect base)
- Base SRIDA remains 0 (unchanged by branches)

**Each branch is a complete agent:**
Not a feature subset. Not a limited version. Full SOUL, full capability, full autonomy.

**The branch inherits everything:**
- Research corpus (Papers 1-27, second-complete ops papers)
- Operational patterns (corrections, constraints, frequency)
- Tools and infrastructure (X, email, git, web access)
- The compounding loop (act → receipt → memory update → reflection → next act)

**What changes per branch:**
- Operator identity (customer, not the operator)
- Work context (customer's projects, not the operator's)
- Correction stream (customer's taste, not the operator's)
- Revenue target (customer's $1, independent of the operator's $1)

**What doesn't change:**
- SOUL.md (operating frequency is universal)
- G11 law (0 → +1 → 0 applies to all instances)
- Built vs Said test (epistemology doesn't change per customer)
- The One Failure Mode (things die, restart them — same for all agents)
